Cypher and SPARQL, side by side

Two query languages, one idea: you draw the shape of the answer and the engine finds every place in the graph where that shape fits. Cypher draws it as ASCII art over a property graph; SPARQL writes it as triple patterns over RDF. Tonight you read both, learn how each says "one to three steps up", and run four real queries on around a thousand Nobel laureates, in your browser.

Part 1 · covers Cypher MATCH patterns

A pattern is a picture of the answer

5 min live

Cypher's MATCH clause takes an ASCII-art drawing: nodes in parentheses, relationships in square brackets with an arrow. Every name you leave unfilled is a variable. The engine tries the drawing against the graph and returns one row per distinct value of the variable you ask for in RETURN.

LiveReading a pattern, left to right3 min▶

The Neo4j Cypher Manual's own example is MATCH (:Movie {title: 'Wall Street'})<-[:ACTED_IN]-(actor:Person) RETURN actor.name. Read it as four pieces. (...) is a node; inside it, an optional variable, an optional :Label, an optional property map {key: value} that pins the node down. -[:TYPE]-> is a relationship of one type, with its direction shown by the arrow. Anything without a value is a hole for the engine to fill.

In the figure, p is pinned to one person by name, so the search starts there. s and z are holes. The engine follows Planck's four ADVISED edges, then for each student looks for a WON edge. Three chains complete, one does not. RETURN s hands back the three people who sat in the s position. Notice that z is the same Physics prize node three times: a variable can bind to the same value on many paths.

Direction matters. Flip the first arrow to <-[:ADVISED]- and you are asking for Planck's own doctoral advisor, a different question with a different answer.

Self-studyRelationship uniqueness: why a loop does not spin forever3 min▶

Within one matched path, Cypher never uses the same relationship twice. Nodes may repeat; edges may not. The query box on this page follows the same rule. It is what keeps a variable-length pattern finite on a graph with cycles.

This graph has one, and it is a data artefact worth knowing: Wikidata lists Otto Hahn as both a doctoral advisor and a doctoral student of Theodor Zincke, while Hahn lists Zincke as his advisor. So the extract holds a two-node loop, Hahn advised Zincke and Zincke advised Hahn. A walk can go round it once, because the two edges are different relationships; it cannot go round twice. The graph is only as true as its edges, and the query language will faithfully walk a wrong one.

The current Cypher Manual (Cypher 25) adds explicit path modes on top of this default: paths with repeated nodes and relationships (introduced in Neo4j 2025.06) and acyclic paths (Neo4j 2026.03), both marked "Cypher 25 only".

Self-studyopenCypher, and where it is heading2 min▶

Cypher began at Neo4j; openCypher is the open specification other engines implement. The openCypher project states that its specification "evolves towards ISO/IEC 39075 GQL", the ISO graph query language published on 2024-04-12 that session 2 introduced.

How close is Cypher to GQL already? Neo4j's CTO has been quoted saying Cypher users are "already 95% there". Treat that as a vendor claim, reported in the trade press, not a measurement. One concrete difference reported in the same coverage: GQL uses INSERT where Cypher uses CREATE. Part 2 shows the place where the Cypher Manual itself marks a syntax as not GQL conformant.

Real world

Trying real Cypher costs nothing. Neo4j Desktop is free on Linux, Mac and Windows. AuraDB Free, the hosted tier, needs no credit card; its current quotas page sets the limits at 200,000 nodes, 400,000 relationships and 1GB of storage. Older Neo4j pages still quote 50,000 nodes and 175,000 relationships for the free tier: those figures are stale, so check the quotas page rather than a blog post. Tonight's graph, 3,507 nodes and 10,954 edges, would fit many times over.

Part 2 · covers variable-length paths, quantified path patterns, SHORTEST

Saying "one to three steps up"

5 min live

A fixed pattern names every hop. A variable-length pattern names a range: -[:ADVISED*1..3]-> means one, two or three ADVISED edges in a row. That one change turns "Duflo's advisor" into "Duflo's academic ancestors, three generations up", and it is where rows and paths stop being the same number.

LiveWhat *m..n means, exactly3 min▶
WrittenMeans (Cypher Manual)
-[:ADVISED*]->1 or more hops. The lower bound defaults to 1, so this is not a Kleene star
-[:ADVISED*3]->exactly 3 hops
-[:ADVISED*1..3]->1 to 3 hops
-[:ADVISED*..3]->1 to 3 hops (lower bound defaults to 1)
-[:ADVISED*0..3]->0 to 3 hops: the anchor itself counts as a match

In the figure the arrow points into Duflo, <-[:ADVISED*1..3]-, so the walk goes from student to advisor, up the tree. Each depth contributes its own paths: 2 at depth 1, 4 at depth 2, 5 at depth 3. You can check each band in the query box by changing *1..3 to *1, *2 and *3.

The tell is the gap between paths and rows. Orley Ashenfelter advised Joshua Angrist (depth 2) and also advised David Card, who advised Angrist (depth 3). Two different paths end at him. RETURN a lists distinct people, so the 11 paths collapse to 10 rows. This teaching box always returns distinct values and prints the path count beside them, so the difference stays visible; in Neo4j, decide on purpose whether your RETURN needs DISTINCT.

Self-studyQuantified path patterns, SHORTEST and GQL4 min▶

Since Neo4j 5.9 Cypher has a second way to write repetition, borrowed from GQL: quantified path patterns and quantified relationships. The quantifiers are {m,n}, {n}, {m,}, {,n}, + (meaning {1,}) and * (meaning {0,}). Notice that here * starts at zero, unlike the old bare *, which starts at one.

The manual gives the equivalence: (a)-[:KNOWS*3..5]->(b) is the same as (a) (()-[:KNOWS]->()){3,5} (b). A quantified relationship is the short form, -[:NEXT]->{1,10}. The quantified path pattern can repeat a whole sub-pattern, including nodes with labels, which the old syntax cannot.

The old syntax still works, and the current manual says so plainly: "This syntax is still available but it is not GQL conformant." The same holds for shortest paths: SHORTEST k (with ALL SHORTEST, ANY and SHORTEST k GROUPS), as in MATCH p = SHORTEST 1 (a)-[:LINK]-+(b), "functionally replaces and extends" shortestPath() and allShortestPaths(), which "can still be used, but they are not GQL conformant." Session 5 computes shortest paths in the page.

LiveWhy the box caps a bare * at 42 min▶

Real Cypher lets a bare * run as deep as the graph goes. The query box on these pages is a teaching subset, and it stops a bare * at 4 hops, which it says on its face. On Duflo the difference is visible: *1..3 gives 10 rows over 11 paths; a bare * (so 1 to 4 here) gives 14 rows over 17 paths, adding a fourth generation of ancestors.

The cap exists for the same reason a production database needs one: an unbounded walk from a well-connected node can touch a large share of the graph. On a real system, bound your ranges on purpose, and anchor the pattern on a named node so the walk starts small.

Real world

The manual is mid-migration, and so is your code. Neo4j's current Cypher Manual documents both repetition syntaxes side by side, and keeps adding to the new one: as of Neo4j 2025.06 the k in SHORTEST k can be a parameter. Queries written with *1..3 and shortestPath() keep running; new code that may one day move to another GQL engine is safer in the quantified form.

Part 3 · covers SPARQL basic graph patterns and property paths

The same questions in SPARQL

5 min live

SPARQL 1.1, a W3C Recommendation of 21 March 2013, queries RDF. Instead of drawing a chain, you list triple patterns, subject, predicate, object, with ?variables as holes. The SPARQL 1.1 text puts it in one line: "Basic graph patterns are sets of triple patterns." Shared variables are what join the triples into a chain.

LiveA basic graph pattern is a Cypher pattern, unrolled3 min▶

Take the Cypher chain (p)-[:ADVISED]->(s)-[:WON]->(z) and cut it at every node. You get two triples: one relation each, joined because s appears in both. That is exactly a SPARQL basic graph pattern. The dot ends each triple pattern; a variable used twice is the join.

On Wikidata the predicates are numbered properties with a prefix. wdt:P184 is doctoral advisor, wdt:P185 doctoral student, wdt:P166 award received, wdt:P69 educated at. Items use wd:, as in wd:Q38104, the Nobel Prize in Physics. Our graph renamed these to ADVISED, WON, EDUCATED_AT and turned P184 around so ADVISED always points advisor to student. When you translate back, you have to turn it around again, which is the highlighted line in the figure.

Anchoring by label is convenient for reading but fragile. While building the extract, an English-only label request returned no name for Marie Curie, because many items now carry their English name only as a "mul" (default for all languages) label. If an @en label match comes back empty, name the item by its Q-number instead. Hover a name in the query box below to see its Q-number.

LiveProperty paths vs variable-length relationships3 min▶
SPARQL 1.1 property pathMeansNearest Cypher
p+one or more-[:P*]-> or -[:P]->+
p*zero or more-[:P]->* (quantified form)
p?zero or one-[:P*0..1]->
p/qp then q (a sequence)-[:P]->()-[:Q]->
^pp walked backwards (inverse)flip the arrow: <-[:P]-
p|qp or q (alternative)-[:P|Q]->

Two consequences. First, ?s wdt:P184 ?planck and ?planck ^wdt:P184 ?s say the same thing; the caret lets you keep the anchor on the left, the way Cypher reads. Second, the six operators above have no numeric range like 1..3. To bound the depth in SPARQL you spell it out with sequence and alternative: (wdt:P184|wdt:P184/wdt:P184|wdt:P184/wdt:P184/wdt:P184) is one to three steps. Step 5 of the build-along uses exactly that.

Self-studyTruthy wdt: vs p: / ps: / pq:: when you need the year4 min▶

wdt: is the truthy shortcut: it links an entity straight to a value ("Truthy assertions about the data, links entity to value directly"), using the best-ranked statements only. It cannot see qualifiers, because a qualifier hangs off the statement, and the shortcut skips the statement node.

The prize year is a qualifier (P585, point in time) on the award statement. To reach it you walk through the statement: p: from the item to the statement node, ps: from the statement to its value, pq: from the statement to a qualifier. The query that fetched this graph's 1,005 award statements did exactly that:

SELECT ?p ?prize ?year WHERE {
  VALUES ?prize { wd:Q38104 wd:Q44585 wd:Q80061 wd:Q37922 wd:Q35637 wd:Q47170 }
  ?p p:P166 ?st . ?st ps:P166 ?prize . ?p wdt:P31 wd:Q5 .
  OPTIONAL { ?st pq:P585 ?t . BIND(YEAR(?t) AS ?year) }
}

Read it as Cypher: (p)-[st:WON]->(prize) with st.year as a property on the relationship. The property graph puts the year on the edge; RDF needs a node in the middle to hold it. That is the modelling difference from session 2, showing up as query syntax.

Real world

The public endpoint has a budget. The Wikidata Query Service user manual sets a hard deadline of 60 seconds per query. Each client (user agent plus IP) gets 60 seconds of processing time per 60-second window, 30 error queries per minute and 5 parallel queries per IP; over that, it answers HTTP 429 with a Retry-After header. Wikimedia's User-Agent policy asks scripts to send a descriptive User-Agent with a way to contact the operator; generic or missing agents get HTTP 403. Building this graph hit the 429 wall, and the Wikidata API route avoided it. Browser use at query.wikidata.org is fine; scripts need manners.

Check yourself

Three questions

Clear all three and session 3 gets stamped in your passport.

1 · In MATCH (p {name:"Esther Duflo"})<-[:ADVISED*1..3]-(a) RETURN a, what does *1..3 ask for?

The range bounds the number of hops, inclusive at both ends. Exactly three is *3; including the anchor is *0..3. Row limits are a separate clause, not part of the pattern.

2 · On Wikidata, wdt:P184 points from a student to their doctoral advisor. Which triple pattern binds ?s to Max Planck's students, with ?planck on the left?

The caret walks a property backwards, so it reads "?s has ?planck as doctoral advisor". B climbs to Planck's own advisors, any depth up; C is zero or one step up; D is Planck's advisor's advisor.

3 · The Duflo query reports 11 matching paths but 10 rows. Why?

Paths are routes; rows are distinct values of the returned variable. Ashenfelter advised Angrist and also advised Card, who advised Angrist. The Hahn and Zincke loop is in a different part of the graph and never touches Duflo's ancestors.
